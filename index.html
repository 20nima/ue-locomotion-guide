UE5 Advanced Locomotion Guide

The comprehensive pipeline for Rigify/Blender characters, covering Capsule-Driven locomotion, Root Motion combat, and troubleshooting.

Method A: Capsule-Driven (In-Place)

The standard for modern games. The Character Movement Component handles all physics, gravity, and speed. The Animation Blueprint reads this speed and plays a "treadmill" animation to match it.

1. Blender Preparation

  • 1
    Lock the Root Bone

    Do not animate the root bone moving through space. The character's physical center must remain at world origin (0,0,0).

  • 2
    Constant Speed Loops

    Ensure the start and end frames of your run/walk cycles match perfectly. The feet must slide backward at a perfectly constant speed, otherwise the character will look like they are limping when put into Unreal.

  • 3
    Export via Script

    Use NM Exporter to export the clean base skeleton and the separate run/walk sequences as FBX.

2. Character Blueprint & Rotation

Open your BP_ThirdPersonCharacter. How your character handles rotation defines your game's feel.

Mode A: Shooter / Strafing (Lock to Camera)

The character body always faces forward. Pressing A or D plays left/right animations.

  • ❌ CharMovement Component: Uncheck Orient Rotation to Movement
  • ✅ Pawn (Self): Check Use Controller Rotation Yaw
Mode B: RPG / Adventure (Free Look)

Pressing A physically rotates the character 90 degrees left, playing the Run Forward animation.

  • ✅ CharMovement Component: Check Orient Rotation to Movement
  • ❌ Pawn (Self): Uncheck Use Controller Rotation Yaw

3. Advanced Animation Blueprint

1
The Event Graph

Use Event Blueprint Update Animation. Get the Pawn Owner. Extract Velocity, and use Vector Length to set a Speed float variable. Use Calculate Direction (using the pawn's Base Rotation) to set a Direction float variable (-180 to 180).

2
The 2D Blendspace

Create a Blendspace. Set X-Axis to Direction (-180 to 180) and Y-Axis to Speed (0 to 600).

• Center Bottom (0,0): Idle
• Top Center (0,600): Run Fwd
• Top Left (-90,600): Run Left
• Top Right (90,600): Run Right
• Top Edges (-180/180, 600): Run Bwd.

3
The State Machine

In the AnimGraph, create a State Machine. Add a state called "Locomotion" and plug your Blendspace into it. Add a "Jump" state. The transition rule from Locomotion to Jump is IsFalling == True.

Method B: Root Motion (Anim Driven)

The animation dictates the physics. The physical distance the character covers in Blender is exactly replicated in Unreal. Used for heavy melee combat, dodges, and vaulting.

1. Animating for Root Motion

  • 1
    Drive the Root

    Keyframe the root bone moving through world space. If the character swings a sword and steps forward 2 meters, the root bone must physically travel 2 meters along the Y-axis.

  • 2
    Keep Pelvis Centered

    The pelvis/hips must stay relatively centered above the moving root bone. The root acts as the capsule's center of mass.

2. Unreal Root Extraction

  • 1
    Enable Root Motion on Anim

    Double-click the Animation Sequence in Unreal. In the Asset Details panel, check Enable Root Motion. Verification: The character will stop running forward in the preview window and stay in place. A red line will appear on the floor showing the extracted velocity.

  • 2
    Configure Anim Blueprint

    Open your Animation Blueprint. Click "Class Defaults" at the top. Set Root Motion Mode to Root Motion from Everything (if using it for all movement) or Montages Only (the standard AAA approach for combat).

3. The Montage Workflow (AAA Standard)

In modern games, standard running uses Method A (Capsule). Root Motion is only triggered during attacks using Anim Montages.

Creating the Montage

Right-click your Root Motion attack animation in the Content Browser and select Create > Create AnimMontage. Open the Montage and ensure the timeline is assigned to a Slot (e.g., DefaultGroup.UpperBody or DefaultGroup.FullBody).

The AnimGraph Slot Node

In your AnimGraph, place a DefaultSlot node between your State Machine and your Output Pose. When you trigger the Montage via Blueprint (using Play Anim Montage), it will override the locomotion state machine, take control of the physics capsule, pull the character forward for the attack, and seamlessly blend back to locomotion when finished.

Common Pitfalls & Fixes

Animation pipelines between Blender and Unreal Engine are fragile. Here is how to fix the most common catastrophes.

The "Spiky Monster" Explosion

Cause: Hierarchy Mismatch

This happens when you import an animation exported from a rig with a different hierarchy or bone lengths onto an existing Unreal Skeleton. The vertex skin weights try to follow the new bone translations and violently stretch.

Solution:

Never apply animations from slightly different rigs to a master skeleton. Use Blender's NLA editor to transfer the animation to the exact Master Rig, or use Unreal's IK Retargeter to bake it safely onto the master skeleton.

The "Moonwalk" (Foot Sliding)

Cause: Velocity / Stride Mismatch

In In-Place locomotion, if your character's Max Walk Speed in Unreal is 600, but the animation was created for a character running at 400 speed, the feet will slide across the floor like they are on ice.

Solution:

Adjust the Max Walk Speed in the Character Movement Component to perfectly match the speed the animation was authored for. Alternatively, open the Animation Sequence in Unreal and tweak the Play Rate slightly until the feet stick to the floor.

Root Motion Won't Move

Cause: AnimBP Settings

You enabled Root Motion in the animation, and the red line shows up, but when you play the game, the character plays the animation completely in-place and doesn't move forward.

Solution:

You forgot to tell the Animation Blueprint to process the root data. Open the AnimBP, click Class Defaults, and set Root Motion Mode to Root Motion from Everything.
