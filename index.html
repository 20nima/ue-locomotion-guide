Unreal Engine 5 Locomotion Guide

A comprehensive, idiot-proof manual for taking Rigify/Blender characters into Unreal Engine 5. Assumes zero prior knowledge.

The Two Paths:
  • Method A (In-Place): The Character Movement Component pushes the character. The animation just plays visually on top. Used for running, jumping, falling.
  • Method B (Root Motion): The animation mathematically overrides the Character Movement Component. The exact distance animated in Blender is copied into the game. Used for combat, dodging, and vaulting.

Method A: In-Place Locomotion

Use this for standard WASD movement. It is responsive, highly performant, and standard across the industry.

1. Blender Export Setup

1
Keep the Root at Zero

Do NOT animate the root bone moving through 3D space. The character must run as if they are on a treadmill, perfectly centered over world origin (0,0,0).

2
Constant Speed

Ensure the feet slide backward at a perfectly constant speed. If the character speeds up and slows down during the loop, they will appear to limp in Unreal Engine.

3
Export

Export the FBX. Ensure the armature is the top-most node (no empty groups above it). Only export deform bones.

2. Character Blueprint

Open your BP_ThirdPersonCharacter. Your rotation settings completely change how the game plays.

Shooter Mode (Strafing)

The character always faces the camera. Pressing A/D makes them sidestep (strafe). Required if you have Run_Left and Run_Right animations.

  • 1. Click CharacterMovement in the top-left Components panel.
  • 2. In the Details panel, uncheck Orient Rotation to Movement.
  • 3. Click the very top item BP_ThirdPersonCharacter (self).
  • 4. In the Details panel, check Use Controller Rotation Yaw.
RPG Mode (Free Look)

The character physically turns to face the direction you press. Pressing A makes them turn 90 degrees and play the Run_Forward animation.

  • 1. Click CharacterMovement in the top-left Components panel.
  • 2. In the Details panel, check Orient Rotation to Movement.
  • 3. Click the very top item BP_ThirdPersonCharacter (self).
  • 4. In the Details panel, uncheck Use Controller Rotation Yaw.

3. Animation Blueprint

This tells the engine which animation to play based on how fast the capsule is moving.

1
Event Graph (Math)

1. Open the Event Graph inside your Anim Blueprint.
2. Use Try Get Pawn Owner -> Get Velocity.
3. Plug Velocity into Vector Length. Save this output as a Float variable named Speed.
4. Plug Velocity into Calculate Direction (use Pawn Owner -> Get Actor Rotation for the Base Rotation pin). Save this output as a Float variable named Direction.

2
2D Blendspace

1. Create an Animation Blendspace. Set Horizontal Axis to Direction (-180 to 180). Set Vertical Axis to Speed (0 to 600).
2. Drag Idle to (0, 0).
3. Drag Run_Fwd to (0, 600).
4. Drag Run_Left to (-90, 600).
5. Drag Run_Right to (90, 600).

3
State Machine

1. Open the AnimGraph.
2. Create a State Machine and connect it to the Output Pose.
3. Inside, add a State called Locomotion.
4. Inside Locomotion, drag in your Blendspace. Plug your Speed and Direction variables into it.

Method B: Root Motion Combat

Use this for attacks, rolls, and vaulting. It completely prevents sliding because the animation IS the physics.

1. Blender Export Setup

1
Keyframe the Root

You MUST physically animate the root bone. If the character lunges forward 3 meters with a sword, the root bone must be keyframed moving 3 meters forward on the Y-axis.

2
Center the Pelvis

Keep the pelvis/hips relatively centered above the root bone. Do not leave the root bone behind while the hips fly forward.

2. Unreal Integration

1
Enable on the Asset

1. Double-click the imported Animation Sequence in the Content Browser.
2. In the Asset Details panel on the left, search for Root Motion.
3. Check Enable Root Motion.
Note: If successful, the character will suddenly stop moving forward in the preview window, and a red line will appear on the floor showing the mathematical velocity.

2
Enable in the Anim Blueprint

1. Open your Animation Blueprint.
2. Look at the top toolbar and click Class Defaults.
3. In the Details panel, find Root Motion Mode.
4. Set it to Root Motion from Montages Only.

3. The AAA Hybrid (Anim Montages)

In modern games, characters use Method A to run around, but temporarily switch to Method B during an attack.

1
Create the Montage

Right-click your Root Motion attack animation in the Content Browser -> Create -> Create AnimMontage. Open the Montage and ensure the green track says DefaultGroup.DefaultSlot.

2
The Slot Node

1. Open your AnimGraph.
2. Right-click and add a Slot 'DefaultSlot' node.
3. Place it exactly between your State Machine and the Final Animation Pose.
Why? When you tell the Blueprint to "Play Anim Montage", this node temporarily mutes your Locomotion state machine, takes over the physics capsule using Root Motion, plays the attack, and seamlessly blends back to Locomotion when finished.

Troubleshooting

The "Spiky Monster" Explosion

Cause:

You imported an animation from a slightly different Blender rig (different bone lengths, extra bones, or different rest pose) onto your existing Unreal Skeleton. The vertex weights get confused by the new distances and violently stretch.

Solution:

Never copy/paste raw keyframes between non-identical rigs in Blender. Instead, use Blender's NLA Editor to append the action to your exact Master Rig, or export the animation as a separate skeleton and use Unreal's IK Retargeter to bake it safely.

Foot Sliding (The Moonwalk)

Cause:

In Method A, the speed of the animation's foot stride does not match the physical speed of the Character Movement Component.

Solution:

Go to your Character Blueprint -> CharacterMovement -> adjust Max Walk Speed. If your animation was created for a slow jog, but your Unreal max speed is 600, they will ice-skate. Tweak the max speed (or the animation Play Rate) until the feet stick to the floor.

Root Motion Does Not Move Character

Cause:

You checked "Enable Root Motion" in the animation, but in-game the character plays the animation in place and never actually moves forward.

Solution:

You forgot to configure the Animation Blueprint. Open the AnimBP -> Class Defaults -> set Root Motion Mode to Root Motion from Everything (or Montages Only if you are playing it via a Montage). Also, ensure you are NOT playing the animation directly in a State Machine if you selected Montages Only.
